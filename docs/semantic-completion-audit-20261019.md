# Independent completion audit repair

The old semantic prompt exposed the expected answer and encouraged one-answer justification. Removing that field alone still admitted plausible alternatives and even rejected an unambiguous physical clue in the real-model sample. Structural completeness did not establish that an exclusion was true. The context generator also prohibited descriptive clues, while semantic retries retained broad stems and only changed distractors.

The repair evaluates each completed sentence independently, allows multiple fitting options, excludes only explicit contradictions/grammar failures, and prohibits typicality or unstated assumptions as proof. The model cites numbered original fragments; the server derives the fitting letters and validates grounded teaching evidence before comparing with the internal answer. New method metadata binds the actual context, option identities and correct word, allowing letter rearrangement while rejecting input drift. Default generation cannot republish an obsolete audit checkpoint; it rechecks only the audit stage. A non-unique context is regenerated with a distinguishing clue and its rejected stem survives retry normalization.

The semantic policy and learning/reward rules remain unchanged. Legacy approved supply stays compatible until reviewed or replaced; there is no release-time whole-cache purge or historical backfill. Existing JSON columns carry the extra metadata, so no migration or frontend interface change is required. The paired frontend continues rendering the saved teaching fields and ignores extra proof metadata.

Validation before release: the first complete backend run had 1303 tests, 1296 passed and 7 existing conditional skips. Later context-retry changes were checked only in affected files (60 passed); clue-index/cache-proof checks had 46 passed, and real MiniMax samples covered multiple plausible instruments/coverings/containers/animals, a climate question and positive physical/shape clues. Raw questions, accounts, model usage, repair plans, receipts and history hashes remain in local task evidence rather than this repository. CI will run the exact committed complete suite.

Production repair must preserve original history/score hashes, use conditional owner/meaning/fingerprint checks, retain referenced cache rows, and publish approved pairs through the existing durable lease/checkpoint publisher. A broad external-model run was not executed after approval review rejected its scope; targeted locally identified examples and paired siblings are handled separately. Do not describe local screening or a limited model sample as a complete all-account semantic audit.

Incremental replacement validation found a further failure: one instrument exclusion cited only the standard number of strings, and another reason explicitly admitted a fitting variant while its boolean still excluded it. The final `blind-completion-v2` method therefore challenges every proposed exclusion before approving. This request receives untrusted reasons and completed sentences, never the intended answer, and its response goes through the same four-option evidence checks. An alternate reading, uncertainty, malformed JSON or provider failure cannot fall back to the initial approval. Existing v1 checkpoints must re-audit; no prior approval is relabeled as v2. The real four-question sample rejects both instrument replacements and accepts the elephant/trunk and triangle positives; 111 affected regression tests pass. This adds one model request only for candidates whose first judgment proposed approval.

The bounded production repair also exposed HTTP 200 responses with provider code 2062 (existing Token Plan rate limit) and zero tokens. Generation previously interpreted these as malformed/empty content and continued stage retries. The provider envelope is now checked by semantic review, context generation, distractor generation and HTTPS translation; a typed rate-limit error propagates through fallback catches to the existing durable job backoff after one request. No billing plan, model, credentials or global concurrency setting is changed. Offline regression reproduces the exact envelope and verifies one-request behavior including translation, plus 237 affected tests passed with four existing conditional skips. Supply replacement and final live submission remain incomplete while the provider rate limit prevents replenishment; do not equate deployed code with complete data repair.

Generation retry feedback now carries the actual alternative words the semantic audit found possible. These hints survive a same-meaning checkpoint resume, clear on a material meaning change, and expire when the pending candidate is approved; they are not a permanent vocabulary blacklist. The next context must add a concrete part/action, and the next distractor set cannot immediately reuse those demonstrated alternatives. Generation names the broad category before choosing members, avoiding a retreat into unrelated objects when close subtypes fail. The existing part-of-speech, difficulty, pair-overlap and semantic proof gates remain intact. A real guitar sample first reproduced fitting string-instrument alternatives; the repaired sample retained a fretted-neck/strumming clue, selected trumpet/flute/trombone, and passed both semantic judgments. No production cache was written by these probes.

Further real-model calibration distinguished recognized variants from imagined modifications. The reviewer had accepted a hypothetical bristled electric razor as an alternative, despite identifying no real variant. The prompt now explicitly retains ordinary literal senses and recognized variants, while forbidding invented designs and treating a cover/component as the whole item. `certain` describes confidence in the four fit judgments, not whether a unique answer exists; unresolved judgments still fail closed. The exact same electric-toothbrush question changed from unsupported multiple fits to a grounded unique result, while the ordinary-instrument and actual six-string-variant counterexamples remain rejected. Ten bounded practice-repair proposals received genuine two-stage approvals and passed the normal local builder/pair validation. Existing parser, evidence, input-binding, uncertainty and approval gates are unchanged; no earlier approval is fabricated or relabeled. After the first authorized 831-row pass, only unresolved responses or explicit suspect variant reasoning receive an incremental follow-up, with both verdicts retained.
