# Independent completion audit repair

The old semantic prompt exposed the expected answer and encouraged one-answer justification. Removing that field alone still admitted plausible alternatives and even rejected an unambiguous physical clue in the real-model sample. Structural completeness did not establish that an exclusion was true. The context generator also prohibited descriptive clues, while semantic retries retained broad stems and only changed distractors.

The repair evaluates each completed sentence independently, allows multiple fitting options, excludes only explicit contradictions/grammar failures, and prohibits typicality or unstated assumptions as proof. The model cites numbered original fragments; the server derives the fitting letters and validates grounded teaching evidence before comparing with the internal answer. New method metadata binds the actual context, option identities and correct word, allowing letter rearrangement while rejecting input drift. Default generation cannot republish an obsolete audit checkpoint; it rechecks only the audit stage. A non-unique context is regenerated with a distinguishing clue and its rejected stem survives retry normalization.

The semantic policy and learning/reward rules remain unchanged. Legacy approved supply stays compatible until reviewed or replaced; there is no release-time whole-cache purge or historical backfill. Existing JSON columns carry the extra metadata, so no migration or frontend interface change is required. The paired frontend continues rendering the saved teaching fields and ignores extra proof metadata.

Validation before release: the first complete backend run had 1303 tests, 1296 passed and 7 existing conditional skips. Later context-retry changes were checked only in affected files (60 passed); clue-index/cache-proof checks had 46 passed, and real MiniMax samples covered multiple plausible instruments/coverings/containers/animals, a climate question and positive physical/shape clues. Raw questions, accounts, model usage, repair plans, receipts and history hashes remain in local task evidence rather than this repository. CI will run the exact committed complete suite.

Production repair must preserve original history/score hashes, use conditional owner/meaning/fingerprint checks, retain referenced cache rows, and publish approved pairs through the existing durable lease/checkpoint publisher. A broad external-model run was not executed after approval review rejected its scope; targeted locally identified examples and paired siblings are handled separately. Do not describe local screening or a limited model sample as a complete all-account semantic audit.
